# 架构与技术决策

状态：此文记录最初候选与持续有效的业务/性能边界。2026-09-30已在[最终架构](08-最终架构.md)确定新版工程结构与技术选择；具体已实现能力、命令与验证见[基础工程交付](09-基础工程交付.md)。已确定云端网站、电脑和平板共用数据；不依赖家中电脑保持开机。

## 1. 系统边界

浏览器通过同域 HTTPS 访问前端和 /api/v1。服务端负责身份、授权、学习事实、金句分配、建议依据、附件与 AI 请求。关系数据库是业务事实来源；私有对象存储保存附件；浏览器仅保存界面状态及未提交草稿。

第一版是模块化单体，前端单独构建，后端一个业务服务和一个可独立重启的后台任务进程。附件缩略图、PDF指定页面预览和 AI 调用异步处理。第一版须可查看用户保存的PDF页面；具体采用浏览器查看还是服务端渲染在P0试验确定，预览失败保留原文件并明确状态。任务状态持久化到数据库，进程退出后可重试；业务提交不等待 AI。

不需要微服务、执行节点平台、知识图谱或向量数据库才能完成第一版。离线跨设备同步不属于已确认范围；断网可保留草稿，明确显示未同步，恢复网络后由用户确认提交。浏览器不是永久学习数据的唯一存储。

## 2. 候选技术与决策理由

| 层 | 推荐候选 | 用途与代价 |
| --- | --- | --- |
| 前端 | TypeScript + React + 常规构建工具 | 页面与状态拆分、静态类型；需建立组件和状态边界，框架不能自动保证设计质量 |
| 后端 | Python + FastAPI | 请求校验、OpenAPI契约、模块路由；需标准部署服务器、授权与事务，不能靠框架默认值完成安全 |
| 数据 | PostgreSQL + ORM + 显式迁移工具 | 事务、关系约束、跨设备写入；比单文件数据库多一项运维成本 |
| 附件 | 私有对象存储及短期授权下载 | 数据库只放元信息；预览、清理、备份需与数据库协调 |
| 部署 | 单云环境、同域反向代理、容器化 | 开发/预发布/生产隔离；托管平台及具体供应商待成本和访问实测 |

这些是工程判断，不是“必须换框架才会快”的结论。保留 Python 便于已有能力迁移，但不复制旧实现。版本、依赖许可、安全更新、锁文件及容器基线在实现开始时确认，避免把今天的版本写成永久要求。

依据：[React 组件与状态](https://react.dev/learn)、[FastAPI 类型与接口文档](https://fastapi.tiangolo.com/)、[PostgreSQL 备份恢复](https://www.postgresql.org/docs/current/backup.html)、[SQLAlchemy 版本计数](https://docs.sqlalchemy.org/en/20/orm/versioning.html)。资料确认日期 2026-09-30；方案优劣仍需本项目实测。

## 3. 模块与依赖

| 模块 | 职责 | 禁止承担 |
| --- | --- | --- |
| 身份与设备 | 登录、会话撤销、资源归属 | 学习决定 |
| 学科目录 | 科目、章节、知识点 | 自动判定掌握 |
| 学习会话 | 开始、结束、继续现场、草稿 | 强制任务分配 |
| 答题与证据 | 独立程度、核对、结果、错误、卡壳、代表题 | 用 AI 文案替代原始事实 |
| 内容 | 金句轮次、偏好、学习方法 | 重度游戏化 |
| 建议与变化 | 可追溯规则、理由、忽略与稍后 | 建议变成债务 |
| 附件 | 授权、上传、关联、预览、删除 | 默认公开链接 |
| AI 顾问 | 受限上下文、解释、失败恢复 | 直接写入掌握或偷偷安排学习 |

UI → API → 服务层 → 数据/对象存储。跨模块通过服务契约调用。首页聚合读取不承担更新学习事实。统计为事实的投影，可重算，记录订正后须更新而不是继续显示旧结论。

## 4. 一致性、时间与故障

写操作有请求幂等标识；修改有资源版本；冲突返回 409 并展示两份内容，不允许后写静默覆盖。每个用户最多一个尚未结束的学习会话（active/paused合计），电脑和平板显示同一会话；用户可以取消或完成后开始新的会话。

数据库保存 UTC 时间，用户时区初始 Asia/Shanghai。学习日、金句、收尾按用户时区计算。修改时区不改历史学习日归属；正在进行的会话保留开始时区。跨午夜时长按实际时间，会话及所属反馈的学习日固定为开始时区的开始日，晚到反馈和补核对不改变归属。

数据库事务负责会话及反馈关联；对象存储与数据库之间用待确认上传、校验、最终关联和过期清理处理，不能假装跨存储存在原子事务。AI失败不回滚已经保存的学习事实。

## 5. 性能预算（验收目标，尚未测试）

基准数据集：一个账号 10,000 条答题记录、2,000 学习会话、1,000 附件元信息；20 个并发活跃会话。附件二进制不包含在首页响应中。

- 普通列表及写入 API：预发布同区域测试 p95 ≤ 500ms，错误率 < 1%；AI与上传另测。
- 首屏：指定电脑和平板、10Mbps/100ms 网络，LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1；测量工具、设备、冷缓存及样本须记录。
- 列表服务端分页，默认20、最多100；首页只取摘要和少量记录；详情与附件懒加载。
- 同一事实保存成功后另一设备主动刷新立即可见；前台自动刷新目标 ≤ 10秒。它是产品目标，不是离线同步承诺。
- AI超过30秒仍未完成显示可重试状态，原始内容保留；预算与超时值可调，不保证模型本身满足首屏预算。

未达预算先定位查询、渲染和网络，不能用缓存掩盖数据错误。增加 Redis 或扩容须有瓶颈证据。

## 6. 身份、隐私与运维

初版默认邀请/管理员创建单人账号，不开放公开注册，保留多用户归属隔离。浏览器用 HttpOnly、Secure、SameSite 的服务端会话 cookie；同域写请求校验 CSRF。密码使用维护中的密码哈希库；登录限速、退出撤销、过期会话必须测试。

任何ID访问都验证当前用户归属。数据库与对象存储不暴露公网管理端口；附件下载授权短时有效。密钥只在服务器密钥配置中，不进前端、日志或源码；日志不记录题目全文或附件内容。

健康检查区分存活与数据库可用性；日志有请求ID、错误码、耗时。部署和迁移记录版本；备份包含数据库、对象及关联清单；定期在隔离环境恢复验证。初步目标 RPO ≤ 24小时、RTO ≤ 4小时，须按实际备份频率和恢复演练校验后才能承诺。
