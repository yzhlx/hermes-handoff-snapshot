# 实施与迁移计划

状态：完整产品实施计划。2026-09-30已完成08架构定稿和09记录的基础工程/学习会话切片；P0至P5全部能力并未完成，真实生产迁移和发布未执行。

## 1. 文档冻结与原型

先确认技术候选、账号方式、附件限额、既有数据是否迁移。按产品文档绘制首页→开始→结束反馈→继续/复习的电脑及平板原型，使用明确标注的示例记录。验证触摸、横竖屏、软键盘和信息层级。用户评审通过后固定第一轮原型，原型不能伪装生产实现。

## 2. 分阶段实现

| 阶段 | 交付 | 完成门槛 |
| --- | --- | --- |
| P0 基础 | 新项目、CI、登录、数据库迁移、同域HTTPS预发布、统一错误 | 健康检查、空库迁移、授权隔离、会话撤销通过 |
| P1 学习闭环 | 五科/自由学习、会话开始结束、独立程度/核对/结果、卡壳、继续上次 | 电脑保存→平板看到→刷新/服务重启仍存在；重复提交不重复记录 |
| P2 数字书房 | 每日金句、收藏不喜欢、首页区域、学科章节知识点、五种方法和情境入口 | 日内一致与整轮不重复；所有空状态与选择自由验收 |
| P3 证据与复习 | 附件、代表题、掌握参考、错误统计、可忽略建议、双例对比、真实变化 | 附件越权与失败恢复、未核对不推掌握、证据可追溯 |
| P4 反馈与顾问 | 每日收尾、节奏、噜噜轻陪伴、AI解释与失败降级 | 不打扰学习、无惩罚措辞、AI失败基础闭环可用 |
| P5 发布 | 性能、完整回归、备份恢复、生产部署和回退演练 | 全部第一版验收通过；无未解决数据丢失/越权/保存错误 |

P1是可运行验证切片，不是第一版全部完成。阶段不表示永久砍掉功能；第一版最终范围以原始需求第55节及验收矩阵为准。

## 3. 协作规则

一个协调者管理需求和接口变更；产品/前端、数据/后端、验证/发布可以分工。每个任务指定文件所有者、依赖、验收和交接，接口冻结后再并行实现。评审者查看实际差异及检查输出，不能只听实现者汇报。不要让多个Agent同时修改同一入口或数据库迁移。

每个阶段形成可回退提交；每次修改必须对应commit并更新相关测试/验证。测试失败保留证据，禁止删测试换取通过。编写应用代码时先运行受影响测试基线，再修改，再复测；仅文档修改使用文档验证。

## 4. 数据迁移（未获执行授权）

默认新项目新库，不自动连旧生产库。用户选择迁移后：只读盘点→备份与恢复试验→字段映射→隔离副本迁移→数量/关系/附件哈希核对→人工抽查→用户验收→维护窗口切换。

旧任务、对话、学习状态不能无证据转换成新答题正确或掌握事实。无法映射的保留历史档案并标注来源；旧附件不存在时报告缺失，不生成假文件。迁移工具可重复运行、映射ID可追溯、失败停止，真实密钥重新配置而非复制。

切换前确定回退时间窗口与切换后新增记录的导出方案。不能简单回旧库而丢掉新记录；出现严重问题暂停写入并保存增量，评估回放或修复。原库和旧应用保留到验收及恢复窗口结束，由用户决定处置。

## 5. 发布验收

使用独立账号、临时数据库和测试附件；电脑Chrome/Edge与真实平板浏览器至少各一次真实操作。跨设备学习、上传、返回现场、核对、复习、订正、AI失败、权限、备份恢复形成证据。

生产发布另行确认具体环境与费用；运行发布前全部检查、冻结构建及依赖、备份、迁移、健康检查和灰度人工确认。记录构建版本和回退操作，不在本次文档任务执行上线。
