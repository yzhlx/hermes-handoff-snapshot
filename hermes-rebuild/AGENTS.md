# Hermes 新项目协作规则

此目录包含重写设计文档及已获用户授权的前后端分离基础工程。工程边界以08最终架构为准，实际能力与验证以09交付记录为准。复制到独立新项目后本规则适用于新版实现；不要继承旧项目的本地Windows运行边界。

- 产品依据原始需求、用户明确确认和需求验收矩阵。已确定云端网站，电脑和平板共享服务端数据。
- 用户自主决定学什么；建议可忽略；不做任务欠债、惩罚或自动掌握判定。
- 先读README及契约，明确任务范围与验收；架构推荐未实测前不得声称已验证。
- 未获实现指令时只修改文档。真实数据迁移、公开发布、付费服务、真实模型调用需用户授权。
- 每次改动完成后，都必须创建一个对应的 Git commit，以便后续追踪和回滚。
- 每次改动后，都必须编写或更新相关测试，并在交付给用户前，确保所有测试和验证全部通过。仅文档修改执行文档检查，不能宣称应用测试通过。
- 测试只用隔离数据库、测试附件和AI mock。不可删除失败测试或降低断言以隐藏问题。
- 单文件明确所有者，接口变化先更新契约再协调；评审依据实际差异与验证日志。
- 学习写入需授权、幂等、事务及版本冲突保护；附件私有；密钥不入源码、浏览器或日志。
- 每次交接记录修改、命令、结果和限制。PASS只用于已执行检查，设计和目标标PLANNED/NOT COVERED。
