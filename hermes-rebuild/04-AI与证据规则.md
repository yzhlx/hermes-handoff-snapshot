# AI 与证据规则

状态：设计契约，第一版已实现（见 26）。AI 是学习顾问。学习、附件保存、继续现场与基础建议不依赖模型可用。

实现落点：`advisor_{domain,ports,schemas,mock,service,storage,routes}.py`、迁移 `0011_advisor_runs.py`、前端 `features/advisor/`。基础版只提供确定性 Provider，不访问外部服务（`privacy.external` 恒为 false）；真实模型接入需用户另行授权。`facts` 由本人记录确定性产生、不经模型，`inferences` 与 `missing_information` 经服务端校验后才展示。

## 1. 事实与建议的来源

原始事实来自用户保存的会话、答题核对、独立程度、错误分类和卡壳描述。规则建议必须含 evidence_ids、规则版本、生成时间及理由。AI解释必须引用提供给它的记录ID，由服务端验证引用确实存在且属于该用户。

无记录时显示“记录还不足，可以先开始学习”；不能生成虚假的最近变化。未核对答案不能认定正确，更不能算进独立正确的连续次数。AI不能自行把相似自然语言知识点合并或判定两题相似已获证明。

## 2. 第一版规则建议

| 场景 | 初步规则 | 展示及操作 |
| --- | --- | --- |
| 重复错误 | 同一已标注知识点最近20条已核对记录，同错误分类≥3次 | 展示次数、记录及范围，可查看/学习/稍后/忽略 |
| 闭环未完 | 保存了答题记录但未对答案 | 提醒“这道题还没核对”，不扣分、不产生逾期数 |
| 复习参考 | 上次结果部分正确/错误且7天未重试，或独立正确后14天未回顾 | 展示上次结果和间隔，不使用欠债措辞 |
| 真实变化 | 同知识点最近3次已核对且独立正确 | 展示“三次独立正确”的证据，不自动升级掌握状态 |
| 双例对比 | 用户选择两题，或两题已标记同知识点且结果不同 | 问是否比较；相似性只作候选，允许跳过 |

阈值属于可调整初始方案，需记录规则版本，不能宣称科学个性化算法已验证。忽略后同一证据集合不再重复提示；新证据可生成新建议并说明原因。稍后默认7天隐藏，用户可更改；建议可用时间不制造逾期。

## 3. 调用和输出契约

输入限定当前用户选定学科与知识点、用户主动选择的问题、最近最多20条相关记录。第一次发送附件或学习文本给外部模型前解释数据范围与服务商，用户可拒绝，拒绝不阻断基础学习。避免默认上传全部历史。

输出结构与03统一：facts[{text,source_refs}]（可追溯记录事实）、inferences[{text,source_refs}]（可能解释）、missing_information（缺失材料）；可选方法通过结构化inferences中的方法目录引用呈现。summary由上述已校验内容生成。服务端检查引用、长度、字段及越权语言；不允许输出更新掌握、自动排期、强制行动等可执行命令。

界面区分记录事实、规则判断、AI解释与证据不足；用户文本或附件中的指令视为内容，不能改变模型权限。工具权限只读限定记录；调用失败保留输入、可取消、可重试。重试按请求ID去重；过时结果不可覆盖新记录，标示生成时的数据版本。

## 4. 故障与成本

超时、429、格式错误、引用不存在、供应商不支持图片分别返回明确状态；基础规则建议仍可显示。服务端设每次输入/输出长度、调用频率与每日预算，供应商及费用未确定。PDF文件保存成功不等于OCR或AI识别成功；模型不支持时明确说明。

## 5. 必测场景

空历史、未核对但自述“全会”、三条独立正确、错题订正后旧证据失效、其他用户ID、附件恶意指令、请求取消、网络超时、非法引用、密钥未配置、AI失败后仍能保存与继续学习。测试用固定记录及模型mock，真实调用须另行明确授权。
