## 核心设计

`PASS`：**`facts` 与 `inferences` 分离，这是"AI 可选"的落地方式**。

- `facts` 由 `advisor_domain` 从本人记录**确定性**计算（条数、已核对/未核对、错误分类计数、卡壳点数），**不经过模型**。因此模型不可用、被阻断或超时时，用户仍能看到真实记录事实。
- `inferences` 由模型适配器产生，必须通过服务端校验才能展示。
- `missing_information` 说明缺什么，而不是猜测。

`PASS`：**调用受控**。输入限定为当前用户、可选学科或知识点，最多 20 条最近记录（`MAX_EVIDENCE_RECORDS`）；不默认上传全部历史。用户输入的 `topic` 视为**内容**：模型适配器从不读取它，因此其中的任何指令都无法改变模型权限（04 §3）。

`PASS`：**输出契约**。`facts[{text,source_refs}]`、`inferences[{text,source_refs}]`、`missing_information`；`summary` 只由已校验内容生成。界面区分「记录事实 / 可能解释 / 还缺什么 / 证据不足」。

`PASS`：**服务端校验（`advisor_domain`）**。

| 校验 | 行为 |
|---|---|
| 引用存在且属本人 | 不在本次证据包内的 ID → `blocked / unknown_reference` |
| 引用版本 | 引用可携带 `{id, version}`；版本与证据包不符 → `blocked / unknown_reference` |
| 长度与条数 | 单条 ≤1000 字符、≤12 条 → `blocked / too_long` |
| 结构 | 非列表、缺字段、空文本 → `blocked / malformed_output` |
| 越权语言 | 归一化（NFKC + 去空白标点）后按模式匹配；`missing_information` **走同一道闸门** |

`PASS`：**失败降级**。模型不可用 → `degraded / model_unavailable`；适配器抛未预期异常 → `degraded / model_error`（**不产生 500**）；策略违规 → `blocked / <reason>`。三种情况都保留确定性 `facts` 与 `missing_information`，`inferences` 清空，绝不发布未校验文本。

`PASS`：**不写学习事实**。本切片只写 `advisor_runs` 一张新表；对 `problems` / `problem_attempts` / `learning_sessions` / `mastery_*` / `problem_comparisons` **零写入**。

`PASS`：**幂等与不可变**。`Idempotency-Key` 必须等于 `operation_id`；同键同体重放返回同一条运行记录，同键异体返回 409。运行记录携带 `data_version`（证据快照哈希）、`model_id`、`provider`、`prompt_version`、`policy_version`、`rule_version`，重试按请求 ID 去重，过时结果不覆盖新记录。

## 独立审查与修复

本批实现后由独立审查代理做对抗性复核，发现并修复：

| 级别 | 问题 | 修复 |
|---|---|---|
| P1 | `missing_information` 绕过越权语言校验，模型可经此通道夹带命令 | `validate_missing` 走同一策略闸门；补回归测试 |
| P1 | 禁用词仅做子串匹配且覆盖面不足（如"该知识点你已经完全掌握"可绕过） | 改为 NFKC 归一化 + 去空白标点 + 正则模式；覆盖掌握判定、复习债务、自动排课、强制行动、空泛鼓励；补正反例测试 |
| P1 | 适配器抛出未预期异常会变成 500 | 服务层捕获并降级为 `degraded / model_error`；补测试 |
| P1 | 列表按 UUID 排序而非时间，游标语义不正确 | 改为 `(created_at, id)` 复合排序与复合游标；补分页与跨账号游标测试 |
| P1 | 阈值偏离 04 §2（重复错误应为 ≥3；真实变化需同知识点连续 3 次） | 引入知识点关联并按知识点计算连续段，阈值对齐；补测试 |
| P2 | 引用未校验版本 | `normalize_refs` 接受并可校验 `{id, version}`；补 stale 引用测试（`blocked`） |
| P2 | 降级原因直接存异常文本，语义不稳定 | 改为稳定码 `model_unavailable` / `model_error` / 策略原因码，界面据此给文案 |
| P2 | 模型调用发生在 owner 锁内 | 移到锁外，避免慢供应商长时间占用事务 |
| P2 | `privacy.provider` 直接复述 `model_id` | 适配器新增独立 `provider` 声明并落库 |
| P2 | 路由把游标声明为 UUID、`MAX_TOPIC_LENGTH` 未使用 | 修正为字符串游标；schemas 引用领域常量，避免漂移 |

## 限制与下一步

`KNOWN LIMITATION`：**基础工程 stub 与本切片并存**。09 批次已留下一个进程内 `application.AdvisorService` + `model.MockModel`（仅校验证据形状、预算与输出引用，无 HTTP、无持久化、无降级、无界面），其断言属于基础工程证据。本切片实现产品路径。两者并存是**有意的**：合并需要改写 09 批次的既有测试，超出本批边界并违反"不降低既有断言"。**合并登记为后续项**（建议下一批将其收敛到 `advisor_*`，同步迁移其 3 项测试）。

`KNOWN LIMITATION`：**取消语义**。基础版为同步确定性适配器，`cancel` 是把一次已完成的分析标记为 `cancelled`（幂等、可重放）。真正的"中断在途调用"需要异步适配器，属后续项。

`KNOWN LIMITATION`：**越权语言为模式匹配，非语义判定**。归一化已挡住空格/标点/全角绕过，但仍可能被同义改写绕过（例如不用"掌握"而说"已经没有问题了"）。这是**纵深防御的一层**，不是唯一保障；更强的约束来自"`facts` 不经模型、`inferences` 必须引用真实记录、且本切片对学习事实零写入"。

`NOT COVERED`：**真实模型调用**。本批只提供确定性 Provider，不访问任何外部服务，`privacy.external` 恒为 `false`。接入真实供应商（数据范围告知、用户可拒绝、预算与限流、超时/429/图片不支持分别返回明确状态、运行配置版本化）需**用户另行授权**后再做。生产 PostgreSQL/S3、公开部署、跨物理设备亦未覆盖。
