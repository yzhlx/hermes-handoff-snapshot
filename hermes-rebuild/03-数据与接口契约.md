# 数据与接口契约

本文定义全新 Hermes 云端网站的完整产品数据与 API 目标契约，面向同一用户在电脑和平板上使用同一份记录的场景。2026-09-30基础工程按08架构定稿实现一个有限切片，已实现端点以生成OpenAPI及09交付状态为准；本文其他实体、端点及高级语义仍是待实现计划，不能仅凭此文宣称存在。实现不依赖旧项目的代码、数据库或路由；旧数据导入另立方案，不作为上线默认动作。

目标生产关系数据库已按08选定PostgreSQL；本地演示和隔离测试可用SQLite，生产事务、并发、备份恢复和部署成本仍须在真实目标环境验证。附件计划使用私有对象存储，数据库保存授权和索引，不保存整份文件。HTTP JSON API作为首版边界；不要求WebSocket，也不承诺离线自动合并。

## 1. 全局约定与数据边界

- 私有实体以 UUID `id` 标识，含 `owner_id`、`created_at`、`updated_at`、正整数 `version`。公共方法、金句目录不含 `owner_id`。时间戳使用 UTC ISO 8601，展示和日汇总使用账号 IANA 时区，默认 `Asia/Shanghai`。
- 服务端从认证会话取得 `owner_id`，不得相信客户端传入的用户标识。每次读取、修改、附件签名、AI 取上下文均重新验证所有权。查询不属于该用户的 ID 返回统一 `404 RESOURCE_NOT_FOUND`，避免泄漏资源存在性。
- 外键必须验证同一所有者。可采用 `(id, owner_id)` 联合唯一键和联合外键。知识点必须属于所选章节和学科；题目关联知识点允许多个，但不能跨账号。
- 可变私有资源每次事务成功更新 `version`，创建从 1 开始。幂等重放不会增加版本。删除保留最少必要墓碑，用于跨设备识别删除；具体留存与永久清理按第 9 节执行。
- 非空标题裁剪首尾空白后 1–200 字符；目标和恢复说明最多 2,000 字符；卡壳一句话最多 1,000 字符；题干、解答及笔记各最多 20,000 字符。空字符串规范化为 `null` 的字段必须在端点文档中注明。列表默认 20、最多 100 条，以稳定的 `(created_at, id)` 游标分页。
- 首版不把打开页面、阅读答案、在线时长当成学习成果。原始记录、用户判断与派生建议分开保存。
- 库中不存 AI 明文密钥、登录密码明文、签名下载 URL 或附件正文。密钥由服务端秘密管理方案持有，具体服务商另行评估。

## 2. 实体与关系

下表是逻辑模型，字段足以决定行为；实际迁移须补充类型、索引、检查约束和迁移测试。

| `attachment_job` | `id`, `owner_id`, `attachment_id`, `kind`, `status`, `attempt_count`, `input_version`, `output_attachment_ids`, `error_code?` | 扫描、预览、可选识别任务；失败不删除原件、不自动保存为已核答案 |

所有私有写入索引至少以 `owner_id` 开头；常用查询补充 session 状态、尝试时间、学科/知识点、建议状态的复合索引。删除业务实体时不允许数据库直接级联删除对象存储；由受控清理任务处理。

## 3. 学习 session 生命周期

学习 session 与认证会话是不同实体。认证失效不能把学习记录结束或删除。

```text
创建 → active ⇄ paused → ended
                    ↘ cancelled
active → ended / cancelled
ended → 创建关联 previous_session_id 的新 active session
```

首版不要求学习前创建草稿：点击开始即创建 `active`；目标、方法、学科可选。暂停/恢复只改变状态与计时片段。页面关闭、网络中断、电脑休眠均不自动写 `ended`，回来仍可恢复；计时片段必须显示用户可校正的异常跨度，不能将隔夜时间默认当作有效学习。**0013 已实现**：单段超过 4 小时或跨越本地学习日时，会话与记录会标注异常并提示确认；用户可把该段改短或声明不计入，**校正只允许缩短**（不能超过已记录或未来的时间），修正前的结束时间保留在 `original_ended_at`；排除的片段不计入 `effective_duration_seconds`。校正不改变学习事实，也不产生掌握证据。

同账号最多一个 `active/paused` session，数据库事务或互斥约束强制执行。另一设备开始时返回现有 session，由用户选择继续或明确结束后再开始，不在后台悄悄抢占。电脑和平板显示的是同一个 session ID，不各自运行独立计时累加。

跨日 session 的学习归属采用开始时区对应的开始日 `learning_date`。后补反馈、后补核答案均沿用所属 session 的学习日，不制造核对当天的虚假新学习。`verified_at` 另存真实核对时间，证据查询可按此字段说明何时形成已核结果。账号修改时区不重写历史 session、日汇总和证据归属；每日金句单独按当前账号当地日期计算。

结束学习写 `ended_at`，关闭计时片段，可附恢复说明。反馈是可后补的独立资源：结束不要求已对答案，`feedback_status` 为派生的 `none/pending/recorded`，`ended` 不表示已掌握。取消只停止 session，已有尝试保留；取消的空 session 不计入有效学习日。对 `ended/cancelled` 进行暂停等非法动作返回 `409 INVALID_TRANSITION`。重复结束使用相同幂等键返回原响应。

“继续上次”优先指向尚未结束的 session；没有时指向最近有实际记录或恢复说明的 ended session。它不成为强制任务。有效学习日指至少有一条有效尝试、回忆反馈或具体学习总结；仅开启计时、点击开始、取消空 session 均不计入。算法版本化， UI 显示口径。

## 4. 作答、核答案与掌握声明

| 字段 | 枚举 | 说明 |
| --- | --- | --- |
| `independence` | `independent/hinted/after_answer/unable` | 独立完成 / 有提示 / 看答案后完成 / 基本不会 |
| `answer_check` | `pending/checked` | 暂时没有核对 / 已对答案；`pending` 不限于没有答案来源，也包括尚未核对 |
| `result` | `null/correct/partial/incorrect` | 只有 `checked` 才能提交非空结果 |

硬约束：`pending ⇒ result=null 且 verified_at=null`；`checked ⇒ result 非空且 verified_at 非空`。未核对可以正常保存、结束和继续学习，显示“待核对”，不能进入正确率分母、独立正确连续次数或掌握证据。错误分类可留草稿，但不能将未核记录汇总成已确认错误。

核对时用户提供结果，服务端记录核对时间；若缺少标准答案，只能保留待核对，AI 的猜测不能充当标准答案。之后更正核对结果必须带版本，保留变更审计，并使相关派生证据与建议失效。错误率分母仅包含已核对尝试，独立正确需同时满足 `independent + checked + correct`。界面标注“按用户记录”，不宣称系统亲自验证算式。

掌握状态是用户自己的大致判断，与证据分开：用户可以声明“可以独立完成”，即使暂无证据，但响应必须带 `evidence_status=unsupported`，UI 显示“自评，暂无已核证据”，不得把这次未核题显示为已掌握或真实进步。证据关联只能使用已核对结果；“独立完成”与“变式稳定”的证据应独立正确，变式稳定还需用户明确标注对应变式依据。无变式证据不得生成“变式已稳定”的客观结论。

证据源被修正或删除后显示 `evidence_status=stale`，原用户声明仍保留，不自动升级或降级。第一版没有自动 AI 掌握评分，没有从学习时长、连续登录、看懂答案推导学会的路径。

“连续三次独立正确”按同一知识点已核对尝试的 `occurred_at,id` 顺序计算，任何已核对的提示作答、看答案作答或错误均打断；待核对记录不能被偷偷跳过宣称连续，应显示“最近三个已核对记录独立正确，另有待核对记录”，并附来源。聚合不得把一题多个知识点关联累加成多道题。

## 5. 每日金句的确定性规则

1. 当天日期由服务端按账号时区计算。第一次请求每日金句在事务中锁定账号金句分配状态，读取/创建唯一 `daily_quote`；并发首次访问只消费队列一次。
2. 队列是本轮启用且未不喜欢的句子随机排列。未完成一轮前不重复；从不喜欢或停用的项目跳过。队列耗尽后新建一轮重新随机。超过一天未访问不预先消耗句子，不积累补展示债务。
3. 新增启用句子随机插入当前轮尚未消费的尾部；已显示句子不可重插本轮。重新启用/撤销不喜欢时，若本轮未消费可插入，否则等下一轮。目录改变须事务化并记录版本。
4. 当日收藏不换句；收藏是跨设备持久操作。点击不喜欢后当前句隐藏，今日返回 `quote=null, reason=disliked_today`，不自动抽第二句，避免刷新换句与日内一致冲突。明日排除此句。空池返回 `reason=no_eligible_quotes`，不能重复抽已不喜欢句子。
5. 收藏与不喜欢可以同时存在：收藏列表仍保留，标注“不再每日展示”，用户可独立撤销收藏或撤销不喜欢。已有收藏的公共金句停用只影响每日展示，收藏记录仍保留文本快照；合法内容删除另有清理规则。
6. 修改账号时区不修改已分配的每日快照；以新时区日期查询时复用相同 `local_date` 的已有记录。不同日期可取得新记录，不能声称时区改动后仍以 24 小时为单位保持一句。首版时区编辑须清楚提示该边界，禁止客户端覆盖日期骗取换句。

## 6. 同账号跨设备一致性

服务端数据是唯一持久状态。首版需联网读写；断网保留表单草稿、明确“尚未保存”，不显示成功、不自动提交过期缓存覆盖另一设备。浏览器私有持久存储不默认保存学习内容；如需要长时离线草稿必须另行确认隐私与冲突方案。

更新请求必须带 `If-Match: "<version>"`；缺失返回 `428 PRECONDITION_REQUIRED`。数据库使用 `UPDATE ... WHERE owner_id=? AND id=? AND version=?`，更新 0 行返回 `409 VERSION_CONFLICT`，附允许访问的当前版本和字段。UI 保留本地输入，显示服务器版本，让用户重新选择；首版不做全文自动合并、不采用最后写入无提示覆盖。

创建资源、状态动作、上传初始化与 AI 请求必须带 `Idempotency-Key`。同账号同操作同键同内容在 24 小时设计窗口内返回相同业务响应；同键不同内容返回 `409 IDEMPOTENCY_KEY_REUSED`。并发同键应等待首笔事务完成或返回明确可重试状态，不能执行两次。24 小时后不能承诺继续重放，客户端应先查原资源再决定重新发起；客户端生成的操作 UUID 可做业务唯一约束补强长期重复防护。短期签名 URL 不进入幂等缓存，需另请求签发。

电脑提交后平板在页面重新可见、路由进入、动作完成时重新拉取对应资源；active session 可做节流轮询，间隔为配置项。首版不承诺毫秒级实时同步。GET 返回 `ETag`，支持 `If-None-Match` 与 304；所有私有响应禁止共享 CDN 缓存。删除后其他设备再次提交返回 `410 RESOURCE_DELETED` 或隐私一致的 404，不重建资源。

## 7. 附件存储、授权与处理

首版建议上限作为待验证配置：图片仅 JPEG/PNG/WebP、单个 10 MiB；PDF 单个 30 MiB、100 页；一题最多 10 个附件。原题文件首版明确限这些类型，不接受任意可执行文件或压缩包。HEIC 等格式不得假装已支持；UI 应指导转换后上传。

```text
pending_upload → uploaded → validating → ready
                                  ↘ rejected
pending_upload → expired
ready → deletion_pending → deleted（删除及回收为后续计划）
```

已实现上传流程：认证后的初始化检查配额，分配内部随机 `object_key`（不下发），客户端使用鉴权/CSRF上传代理传输原始字节，再调用完成接口；服务端检查真实对象大小/hash、魔数、解码、PDF 页数、恶意内容与安全策略。上传成功不是文件已可使用。`ready` 才能绑定题目、通过鉴权下载代理读取或处理；不可信文件隔离，原始文件名仅作为清洗后的显示名。

存储桶禁止公开访问。下载授权在每次请求时检查账号、附件状态和关联权限，建议最长 5 分钟，访问签名可能在撤销后到期前有效，这一边界须明确。更严格撤销需求使用经认证下载代理。列表不返回可永久访问的 URL；日志不记录签名查询串。非图片文件使用安全附件下载响应；预览在独立安全域/沙箱，限制主动脚本内容。

PDF 上传、原件保存、页面预览、OCR/视觉分析是四个不同能力：原件验证可独立 `ready`，预览为异步任务状态；识别失败不阻止查看可下载原件。每页衍生对象记录父附件、页码、处理版本和同账号所有权。第一版 PDF 指定页必须可查看，原件与题目保存不依赖 OCR；页面未能预览时显示失败与原件下载选项，不能声称已完成指定页查看。首版若某阶段尚未实现，API 必须报告 `unsupported`，不把“选中了 PDF”当成完成识别。

题目保存成功必须有可读取正文，或至少一份 `ready` 且已在同一数据库事务中建立 `attachment_link` 的附件。只有 uploaded 或 ready 孤儿对象时，UI 显示“等待验证/等待关联”，不得显示“错题已保存”。对象存储上传与数据库关联无法做同一事务，应以持久状态与补偿清理实现，不把短期失败当永久丢失。

处理任务重试有界、输入版本不匹配取消、不覆盖用户已编辑文字。可选 AI 识别先取得用户明确启动动作，生成可编辑草稿，不直接保存为正式题目、标准答案或核对结果。删除原件前先检查所有题目引用，展示影响范围；解绑不等于删除。无引用 pending 上传建议 24 小时回收，已 ready 孤儿附件建议 7 天回收，均为待验证运维策略，清理任务必须再检查引用以避免并发误删。

## 8. AI 与派生内容边界

请求 AI 只提供当前账号、用户选择的学科/题目/时间范围所需最小上下文；服务端不能让模型自行查询全库。默认最多最近 20 条相关已核尝试、必要卡壳点与用户主动选择附件；不足直接列缺失信息。提交前告知外部服务将处理哪些学习资料；密钥不下发浏览器，不把私有内容写入常规日志。

AI 输入同时包含证据 ID/版本、明确已核与未核状态。输出统一区分 `facts`（可追溯来源）、`inferences`（推断及限制）、`missing_information`（缺少的资料），具体结构与《AI与证据规则》一致。可自由采纳的方法建议属于有依据的推断，不另建自动执行命令。引用不在允许输入集合的 ID 拒绝采用，输出事实须由服务端验证来源，不把格式正确等同事实正确。AI 不能擅自设定今日任务、写掌握状态、提交作答核对或修改用户记录。

生成中原记录修改后结果标为 `stale`，不重新替用户写数据。重复请求用幂等键去重；超时、取消、空响应、格式不符返回任务失败且原输入保留。核心 session、反馈、金句、附件原件不依赖 AI 可用。AI 方法建议可被规则目录替代，但不能伪装为 AI 已分析。

首版规则建议与 AI 分开：重复错误取同知识点最近最多 20 条已核对尝试，同分类至少出现 3 次才提示，并列来源；复习提醒的初始阈值为距相关记录 7/14 天，由结果与类型选择，规则版本化，不宣称科学最优。稍后默认 7 天，也可由用户另选；忽略建议记录证据集合指纹，同一证据集不能再换措辞推回，新证据出现才可生成新建议。accept 只表示接受建议，不代表已复习或已掌握。

## 9. 数据主权、删除与备份恢复

数据属于用户。云端共享意味着数据库、对象存储、备份与可选 AI 服务构成明确外部数据流，不能沿用“数据只在本机”的描述。

上线前必须实现并演练数据库自动备份、私有附件备份/版本保护、恢复到隔离环境、关联完整性核对。建议目标为数据库 RPO 24 小时、RTO 4 小时，具体是否能达到须由恢复演练给出证据，不把目标写成已经兑现的保障。恢复后检查 owner 隔离、题目附件可读、待处理 job 恢复策略、session 状态、幂等记录与日金句一致性。备份密钥独立管理，不把真实数据复制到开发机和测试夹具。

导出与账号删除已实现（0014，见 29）：导出为结构化 JSON，含数据字典与带 sha256 的附件清单，请求身份校验、私有短期下载（`expires_at` 到期后 410），**不导出密码/登录凭据/存储内部标识，也不导出他人数据**。导出依赖稳定 ID 和时间字段，因此从第一版建模开始保留兼容能力。

账号删除已实现两段式（0014，见 29）：逐字确认登记后账号进入 `deletion_pending`、**学习写入暂停**（账号级端点仍可用，否则无法导出或撤销），列明影响范围与撤销窗口；撤销回到 `active`；再次逐字确认后执行清除并保留最少墓碑（`account_deletions` 一行 + `users.status='deleted'` + 凭据作废 + 用户名释放）。清除范围覆盖全部 owner 作用域表（含导出包），**其他账号的数据不受影响**。恢复备份必须重新应用删除清单，防止已删数据复活；确切撤销窗口与备份留存周期待部署评估确定（当前为 `REVOKE_WINDOW_HOURS=24` 的命名常量），在承诺"已永久删除"前必须处理这一边界。

普通题目归档可恢复；永久删除、全量清空、旧系统迁移均需单独方案与用户授权。任何验证使用合成数据和隔离账号，不能对真实学习数据库运行清空测试。

## 10. HTTP API 总契约

根路径 `/api/v1`。下述均为新项目设计端点，未实现前不得暴露假成功。

初版采用邀请/管理员创建账号的内部凭证身份服务，与业务 `account.auth_subject` 关联；不开放公开注册。凭证库以维护中的密码哈希库保存密码哈希，不使用业务 profile 明文存储密码。服务器管理认证会话与安全 Cookie：`HttpOnly`、`Secure`、恰当 `SameSite`；改变状态请求验证 CSRF token 与 Origin。登录限速、退出撤销、到期失效与设备会话撤销必须验证，确切过期窗口、找回与管理员初始化流程在实施前确定。未认证 401；账号停用 403；认证过期的表单输入仍在页面保留，且认证会话不会自动结束学习 session。

成功 JSON 为 `{ "data": ..., "meta": { "request_id": "..." } }`；列表 `data.items` 与 `data.next_cursor`。无实体返回 204；异步任务返回 202 与可查询 job ID。详情响应 ETag 为资源当前版本。错误 JSON：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "尚未核对答案，不能提交正确结果。",
    "fields": { "result": "必须为 null" },
    "request_id": "req_example"
  }
}
```

| 状态 | code 与适用情况 |
| --- | --- |
| 400 | `INVALID_JSON/INVALID_CURSOR`：语法或游标错误 |
| 401 | `AUTH_REQUIRED`：需要登录 |
| 403 | `ACCOUNT_DISABLED/CSRF_REJECTED`：禁止操作 |
| 404 | `RESOURCE_NOT_FOUND`：不存在或不属于本账号 |
| 409 | `VERSION_CONFLICT/ACTIVE_SESSION_EXISTS/INVALID_TRANSITION/IDEMPOTENCY_KEY_REUSED/ATTACHMENT_NOT_READY` |
| 410 | `RESOURCE_DELETED/UPLOAD_EXPIRED`：已删除或授权过期（不得暴露他人状态） |
| 413 | `FILE_TOO_LARGE` |
| 415 | `UNSUPPORTED_MEDIA_TYPE` |
| 422 | `VALIDATION_ERROR/INVALID_REFERENCE`：字段/关系/枚举非法 |
| 428 | `PRECONDITION_REQUIRED`：缺少更新版本 |
| 429 | `RATE_LIMITED/QUOTA_EXCEEDED`：附可安全显示的配额和 Retry-After |
| 500/503 | `INTERNAL_ERROR/SERVICE_UNAVAILABLE`：不返回堆栈、内部路径或密钥 |

## 13. 契约验收要求（待实现，不是已执行测试）

- 两个隔离账号交叉读写 subject、attempt、job、签发附件 URL 均被拒绝；关联他人 ID 不写入任何行。
- 同账号两设备同时开始只产生一个 active session；重复结束只产生一次结束和片段关闭；结束但未核答案不计正确率。
- `pending + correct` 被拒绝；先 pending、后 checked 的记录版本增加且持久；更正证据后摘要/建议失效；AI 无写掌握权限。
- 两设备修改同版本仅一次成功，另一侧收到版本冲突且草稿保留；幂等同键同体重放、不同体拒绝、并发请求只写一次。
- 同日并发请求只分配一句；一轮不重复；收藏不换句；不喜欢当天隐藏次日排除；全句不喜欢为空池；目录增删、时区切换可解释。
- 图片魔数不符、过大、PDF 超页、脚本内容、对象不存在、重复完成、上传授权过期均有稳定错误；预览失败仍保留安全原件；删除与绑定并发不误删。
- AI 超时、返回虚假来源、源记录变更、取消均不覆盖学习输入或伪装真实进步。
- 使用合成学习数据验证 API 写入 → 数据库行 → 重载 → 服务重启 → 另一设备重查；私有附件恢复演练检查引用、hash 与权限。
- 真实云端共享、身份安全、导出删除和恢复能力必须在实施后各自提供验证证据，文档通过只表示规则定义完整。
