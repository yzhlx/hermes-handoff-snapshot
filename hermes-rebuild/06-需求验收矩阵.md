# 需求验收矩阵

状态：本文件是新版实现后的验收计划，全部用例当前均为 `NOT COVERED`；文档检查通过不等于应用功能通过。FR 编号与产品规格一致，[原始需求](原始需求.md)的57节逐节追溯。测试用模拟账户与非私人附件，固定账户时区和时钟，AI 默认确定性模拟。任何 `PASS` 必须附实际执行命令、结果和证据。

测试层缩写：U=规则单元；A=接口/权限/数据持久；E=真实浏览器端到端；V=真实视觉/无障碍；M=用户体验验收。所有写入类用例必须验证浏览器动作→服务响应→数据记录→刷新→服务重启→另一设备读取，不能只测响应成功。关键写入及并发用例至少重复三次。

## 3. 测试数据与证据要求

准备固定样例：无记录账户；五科学习账户；采样三次同类错误；高数三次独立正确；看答案才正确；未核对尝试；多错误原因；两题有相似证据但异结果；有PDF指定页的题目；七天五有效日；全部金句屏蔽；两个账户与两种设备会话。所有名称使用 `QA_TEST_` 或 `E2E_TEST_`，附件使用无版权/隐私问题的人工固定材料。

每次结果记录包含：AC编号、固定数据、执行版本、环境、具体步骤/命令、实际结果、状态、证据路径、未覆盖理由。视觉用五视口截图，权限用接口结果，持久性用数据断言，AI用输入/输出脱敏样例。截图、日志和数据库查询结果不得包含生产学习内容、密码、密钥、令牌。

## 4. 发布门槛

第一版完成条件为 AC-001—AC-057 与 AC-X01—AC-X17 的适用执行层全部验证，用户体验项标记 `MANUAL USER ACCEPTANCE` 并记录用户判断。任何核心保存、共享、附件访问、诚实核对、权限隔离或禁止强迫的失败阻断发布；普通视觉瑕疵记录后修复。`NOT COVERED`、`BLOCKED`、`KNOWN LIMITATION` 不算通过。原文未来能力不纳入失败，原文第一版能力不能借“未来”标签免除验收。

本次仅撰写规格与验收计划，未执行新应用测试、浏览器截图、真实AI或云端部署。实施者须补齐运行证据，不能把这份矩阵中的预期结果当成已发生结果。
